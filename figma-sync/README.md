# Figma Sync Plugin

A Figma plugin (TypeScript, Figma Plugin API) that syncs `fdsi-*` icons between this repo and a Figma library. Each icon is modeled as one ComponentSet with `Size` (sm/reg/lg) and `Style` (outline/solid/color) variant properties.

**Status: implemented, not yet runtime-tested.** Everything here type-checks and builds, but it hasn't been loaded into an actual Figma desktop session or run against a real GitHub repo — validate carefully in a scratch file/repo before pointing it at production.

## Build

```sh
cd figma-sync
npm install
npm run build        # -> dist/code.js, dist/ui.js, dist/ui.html
npm run typecheck     # tsc --noEmit only
```

Then in Figma desktop: **Plugins → Development → Import plugin from manifest…** and select `figma-sync/manifest.json`.

## Settings (stored via `figma.clientStorage`, per Figma file)
- **GitHub token** — a fine-grained PAT scoped to this repo with Contents (read/write) and no PR/branch-protection bypass permissions. Stored client-side; treat it as sensitive — this is a v1 tradeoff (see Known limitations).
- **Owner / Repo / Branch** — target repo and the branch commits are written directly to (no PR step).
- **Brand** — defaults to `core`.

## Features
- **Pull from GitHub** — reads `registry/generated/index.json`, creates/updates a ComponentSet per active icon, skips icons whose content hash hasn't changed, and commits `figma.nodeId`/`lastSyncedAt` back.
- **Push selection** — exports the selected ComponentSets' variants to SVG, resolves each one's canonical name (existing tag, new mapping, or a detected rename — renames auto-append the old name to `aliases` instead of creating a duplicate), validates against the naming convention + `size-tokens.json` px safeguard, shows a file-level diff, then commits everything as one atomic commit on confirm.
- **Check status** — read-only 3-way diff (repo's recorded hash / repo's current content / Figma's current content) that flags `conflict` instead of silently picking a side.
- **Post-publish sync** — re-run manually after you publish the library in Figma's UI (the Plugin API can't trigger publish itself); captures each component's now-available `componentKey` and commits it back.

## Known limitations
- **No PR gate.** Commits land directly on the configured branch. The plugin's own schema/naming/size validation (and the diff preview) are the only safety net — pair this with GitHub branch protection + a CI check if you need a stronger guarantee.
- **`componentKey` requires a manual publish first.** There's no Plugin API method to publish a library; `postPublishSync` only fills in keys for components that are already published.
- **Icon-level hashing, not per-variant.** Any single variant changing marks the whole icon dirty for re-sync purposes.
- **PAT in `clientStorage`** is fine for an internal v1 tool but isn't a secure secret store — revisit a GitHub App + relay backend before wider rollout.
- `registry/generated/*` aggregates are read by Pull but never regenerated by this plugin — still a manual/future-build-script step.
